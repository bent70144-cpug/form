# 07: Form-schema package and draft save API

**Spec:** `../spec.md`

**What to build:** The shared block-schema package and the draft-save and validation API, tested at the API seam. No builder UI is part of this slice.

**Blocked by:** 06

**Status:** done

- [x] The schema envelope from ticket 06 contains `schemaVersion`, title, blocks, logic, theme, and settings; the block union supports welcome, short-text, long-text, and ending blocks. This slice adds validation, limits, and block rules.
- [x] A `migrateSchema` registry stub handles `schemaVersion: 1` as identity; future schema migrations are explicit registered functions, never in-place JSON edits.
- [x] Block IDs are 12-character URL-safe IDs generated by the client on add (nanoid); the server enforces `^[A-Za-z0-9_-]{10,32}$` and uniqueness within the form. IDs remain stable across edit and reorder.
- [x] Only question blocks produce answers; answers are keyed by block ID.
- [x] Draft save replaces the full draft schema atomically; the server rejects duplicate IDs, unsupported kinds, malformed values, unknown fields, and NUL (`\u0000`) characters with stable error codes (`invalid_character` for NUL).
- [x] Structurally valid drafts may have empty labels or titles and may contain no question block. Labels, descriptions, placeholders, and titles are plain text; the renderer escapes them rather than treating them as HTML.
- [x] The draft row starts with integer `draft_version` 0; every successful save increments it. Draft save accepts the last-seen `draft_version`, and any mismatch returns 409 `draft_conflict` instead of overwriting another tab.
- [x] Concrete limits are enforced: form title 200 characters, block label or title 500, description 2,000, placeholder 200, maximum 200 blocks, draft schema 256 KB by bytes, a short-text answer 1,000 characters, and a long-text answer 10,000 characters.
- [x] JSON caps count bytes and govern when per-field maxima would exceed them; the API returns stable `schema_too_large` or `too_many_blocks` codes.
- [x] Draft-save route body limits are set explicitly at about 300 KB; other routes use small explicit limits. The limit is configured rather than inherited from the Express or Fastify adapter's default, and the test asserts the configured value.
- [x] At least one question block, non-empty labels or titles, a welcome block first if present, and an ending block last if present are required at publish, not at draft save.
- [x] The web app consumes the shared schema and contract types; it does not duplicate validation rules.
- [x] API error codes stay stable while human-readable messages come from i18n keys.
- [x] API integration tests cover valid saves, each validation failure, NUL rejection, the character limits, the byte caps, the configured body-parser boundary, block-ID format and duplication, the empty envelope, incomplete-block saves, and the stale-`draft_version` conflict.

## Implementation notes (2026-10-31)

- Web consumes shared contracts + schema (no duplicated rules; import-boundary tests pass). API + form-schema suites green (151 api / 82 form-schema at integration).
